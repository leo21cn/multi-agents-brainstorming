# 规则 03 · 后端 Python 规范

来源：`../../docs/architecture.md` 第 4、6、8 节；`../../docs/data-model.md`；`../../docs/implementation-plan.md`（模块与接口契约）。

## 语言与风格

- Python 3.11+。
- 全量类型标注；公共函数、服务方法、领域实体均标注参数与返回类型。
- 异步优先：接入层与涉及 I/O 的服务用 async；避免在异步路径中做阻塞调用。
- 命名：模块小写下划线；类用帕斯卡命名；常量全大写；与领域术语一致（房间 room、命题 proposition、智能体 agent、知识库 knowledge_base、发言 message、举手 raise_hand、结论文档 conclusion_doc）。

## 分层落位

| 目录 | 职责 |
|------|------|
| `api/` | REST 与 WebSocket 接入、协议转换、请求校验 |
| `services/` | 配置、房间、发言、结论、来源标注等业务用例 |
| `orchestration/` | AG2 适配器、调度策略、待发言队列 |
| `rag/` | 文档解析切分、嵌入、向量库、检索 |
| `memory/` | 上下文组装、滚动摘要、记忆服务（L1/L2/L3） |
| `models/` | 模型提供方接口与 OpenAI 兼容实现 |
| `persistence/` | SQLite 访问与文件系统读写 |
| `domain/` | 实体与枚举 |

- 领域实体用 dataclass 或 pydantic 模型，集中在 `domain/`。
- 服务之间通过领域实体与接口交互，不互相穿透内部实现。

## 错误处理

按 `../../docs/architecture.md` 第 9 节的异常流处理，不吞异常、不静默失败：

- 模型调用超时或失败：上报房间并允许重新点名。
- 检索无命中：标记无知识库引用，不阻断讨论。
- 会话记忆为空：拒绝生成结论并提示。
- 上下文超阈值：先滚动摘要再生成。
- 上传文档格式不支持或为空：拒绝入库并提示。

## 日志

- 记录模型调用、检索命中、发言生成的关键字段（房间、来源成员、模型连接、模型名、引用知识库、耗时）。
- 日志不得包含 API Key 或完整凭据。

## 配置

- 环境级配置（如环境变量提供的默认凭据、阈值与预算）从环境变量读取，集中在一个 settings 模块；不在业务代码散落读取环境变量。
- 模型连接的地址与凭据为系统级可配置项，存于持久层并经掩码读取；API Key 不得下发前端明文、不得入日志与导出。
- 阈值与预算（上下文令牌预算、摘要触发阈值、召回条数）集中配置，不硬编码进业务逻辑。
