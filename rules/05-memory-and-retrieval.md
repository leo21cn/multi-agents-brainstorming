# 规则 05 · 记忆与检索

来源：`../../docs/architecture.md` 第 7 节（记忆架构）与第 6 节（检索服务、发言生成服务）；`../../docs/data-model.md`（记忆相关实体）。

## 记忆与知识分离

- 记忆：房间内讨论产生并沉淀的信息，随房间隔离。
- 知识：系统级三维知识库中的预置语料，跨房间复用。
- 二者在架构上分离：知识经 `rag/` 检索注入发言；记忆经记忆服务维护。不得把知识库当作记忆，也不得把房间转录写入知识库。

## 记忆分层

| 层 | 名称 | 作用域 | 生命周期 |
|----|------|--------|----------|
| L0 | 工作记忆 | 单次发言 | 临时，不持久化 |
| L1 | 会话记忆（转录） | 房间级 | 持久化 |
| L2 | 摘要记忆 | 房间级 | 持久化 |
| L3 | 立场记忆 | 智能体级（房间内） | 持久化 |
| L4 | 长期召回 | 房间级 | 持久化（本版未启用） |

- 写入：每次发言追加 L1；被触发发言的智能体按（房间，智能体）单行覆盖 L3 要点，取该条发言的前 200 字，只保留最新立场而不累积历史；L1 正文字数合计达阈值触发一次压缩——对全量消息重新压出一段摘要并新增一行 L2，其覆盖范围记为首条至末条消息，故每次触发都新增一行而不改写既有行，上下文只取最新一行。压缩为确定性的文本折叠（按序拼接各条正文并截到 600 字），不调用模型。模型生成期间的推理内容不写入 L1 也不写入 L3，只在生成期间经实时通道呈现。
- 读取：按字符预算自高层向低层组装（L0、L2 的最新一行、L1 的最后 20 条原文、L3、知识检索结果），超出预算按该顺序自尾部裁剪。L4 本版未启用，不参与组装。
- L0 含命题与当前焦点（提问者姓名与问题原文），不落库，每次发言前重建。
- 压缩：为具体实现（`memory/compress.py` 的滚动摘要），未抽象出压缩策略接口，替换压缩方式即替换该实现。
- 淘汰：近期原文的窗口恒为最后 20 条，与 L2 的覆盖范围无关，故已被摘要覆盖的原文只要落在窗口内仍进入上下文，摘要块是附加而非替换；原文一律保留在 L1 中供结论生成与导出使用。

## 上下文块序与署名

- 块序固定为：命题 → 当前焦点 → 讨论摘要 → 近期原文 → 立场 → 知识。裁剪按块序 `break`，靠后的块先被牺牲。
- 模型推理内容不属于任一块：它不落库，因而不进入上下文组装，也不得由发言生成链路另行注入。进入上下文的只有已落库的正文。
- 知识检索块排在最后，超预算时最先被裁掉，而来源标注率依赖它。这是既有隐患：预算紧张时发言会退化为无知识库引用。改动块序须重新核对来源一致率与标注完整率两项指标。
- 当前焦点须紧随命题：定向提问是本次发言的直接动因，排在摘要与原文之后会在预算紧张时先被裁掉，受话者因此读不到问题。
- 焦点优先由消息标识锚定：触发本次发言的那条提问以标识随发言请求传入，据此取回原文。多个受话者共用同一条提问、依次应答时，轮到后一个人时该提问已不是房间最后一条，靠「末条」推导必然失效。
- 无锚点时回退由 L1 末条推导：房间最后一条消息若为定向给本次发言者的人类消息，其原文即待答提问；否则无焦点。REST 一次性发言与放行举手走该回退，行为与锚定路径一致。
- 锚点指向的消息不是人类提问、或本次发言者不在其受话者列表内时无焦点：锚点只用于定位待答提问，不得据以改写来源。焦点只描述当前一次发言，不回溯历史提问。
- 近期原文按来源署名后进入上下文，格式为 `[显示名·来源类型] 正文`；消息角色一律为 `assistant`，不按来源切换角色，避免把人类发言伪装成模型自身输出。
- 未注入署名解析器时近期原文取正文原样，不加前缀；该形态仅供不需要区分说话人的调用方使用。
- 署名解析：智能体取其配置名，人类发言按来源标识在房内全部人类成员中取显示名，主持人与各位成员各按自己的名字呈现；落库早于连接级身份的历史行其来源为字面值 `host`，继续按主持人回落；其余解析不到时回退通称或原始标识，不得留空。署名解析失败不得阻断发言。

## 隔离边界

- 记忆不跨房间共享。
- L1、L2 对房间内成员可见，构成所有智能体的共享上下文。
- L3 默认仅服务所属智能体；是否进入其他智能体上下文可配置。

## 发言生成链路

按 `../../docs/architecture.md` 第 9.2 节：发言前以发言意图检索绑定知识库，再读取记忆（L0、L2、L1、L3）连同检索结果组装上下文——检索先于记忆读取发生，故命中直接进入同一次组装；调用该智能体所选具体模型；发言后写回 L1 与 L3，并在达阈值时触发 L2 压缩。

- 检索查询取发言意图，无意图时回退智能体名。定向提问的意图即问题原文，含 `@名字` 记号，不做剥离：该记号是自然语言的一部分，剥离带来的收益低于引入一条专用清洗规则的成本。
- 检索失败（嵌入端点不可达、向量维度不匹配）收束为发言错误，发生在任何增量下发之前，与检索无命中区分处理。

## 来源标注

- 发言记录其引用的知识库来源；检索无命中时标记无知识库引用。
- 结论生成（第 9.4 节）读取命题与该房间的全量发言，不取摘要；关键观点与分歧点由记忆抽取并标注来源智能体，界面与 Markdown 文档只呈现智能体名，所绑知识库保留在来源标注数据（`source_annotations` 与各条的 `source.kbs`）里供追溯；必写章与其后各章的综合以命题、最后 30 条（每条截断至 200 字）讨论记录与已抽取的两章为输入，故同一份发言序列既服务抽取也服务综合。
- 导出以会话记忆为准，按时间逐条保留来源标识，条数与 L1 一致。
- 导出逐条以显示名呈现来源，不落原始标识串；多位人类成员各自按自己的显示名呈现，不得一律记成主持人或回退「人类成员」通称。带受话者的记录逐个追加全部受话者显示名，以顿号连接，智能体在前、成员在后，各自保持落库次序，与界面受话者标签同序。显示名一次遍历取齐，避免逐条查询。
- 导出的正文为落库原文，被截断的记录同样是残篇，故行尾追加截断标注，取落库的截断标记而非重新推断；标注不改变导出条数与 L1 一致的口径。
