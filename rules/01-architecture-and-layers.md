# 规则 01 · 架构边界与分层

来源：`../../docs/architecture.md` 第 4、5 节；`../../docs/implementation-plan.md`（模块划分与接口契约）。

## 依赖方向

依赖只能自上而下，禁止反向与跨层直连：

```
前端层 → 接入层 → 应用服务层 → 编排引擎 / 领域能力层 → 模型适配层 / 持久化层
```

- 前端只经接入层（REST、WebSocket）与后端交互，不得直连数据库、模型或向量库。
- 接入层只做协议转换与鉴权占位，不含业务逻辑。
- 应用服务层承载业务用例，编排房间、配置、发言、结论、记忆。
- 领域能力层提供检索、上下文组装、滚动摘要、来源标注、待发言队列、立场记忆、历史召回。
- 模型适配层与持久化层位于底层，供上层调用。

## 框架与外部依赖隔离

- AG2 只出现在 `orchestration/` 内。其余模块不得直接 `import ag2`；跨层传参用本项目领域实体与接口。
- 模型调用只经 `models/` 的提供方接口；业务代码不得直接调用 DashScope SDK 或拼接其 HTTP 请求。
- 持久化只经 `persistence/`；业务层不得直接写 SQL、读写文件或操作向量库。
- 向量检索只经 `rag/`；业务层不得直接操作向量库客户端。

## 扩展点接入

扩展点接口见 `../../docs/architecture.md` 第 5 节。新增能力一律经接口实现接入：

- 新增编排模式：实现 `SpeakerSelectionStrategy`，不改房间与发言主流程。
- 新增模型提供方：实现 `ModelProvider`，不改发言与检索链路。
- 新增技能：扩展 `Skill`，现为角色提示词卡（纯提示词）。
- 新增成员身份来源：实现 `MemberIdentity`，现为昵称或登录身份。
- 会话通道扩展：实现 `SessionChannel`，现为单机 WebSocket。
- 记忆压缩策略：实现 `MemoryCompressor`，现为滚动摘要。
- 长期召回：实现 `LongTermRecall`，本版未启用。

## 事件与协议一致性

- 房间事件（发言、举手状态、成员变更、房间状态、发言失败提示）在接入层定义，前端 `ws/` 与后端保持同一套类型定义。
- 新增事件类型时，同步更新接入层、前端 WebSocket 客户端与相关服务。
