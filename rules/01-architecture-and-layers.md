# 规则 01 · 架构边界与分层

来源：`../../docs/architecture.md` 第 4、5 节；`../../docs/implementation-plan.md`（模块划分与接口契约）。

## 依赖方向

依赖只能自上而下，禁止反向与跨层直连：

```
前端层 → 接入层 → 应用服务层 → 编排层 / 领域能力层 → 模型适配层 / 持久化层
```

- 前端只经接入层（REST、WebSocket）与后端交互，不得直连数据库、模型或向量库。
- 接入层只做协议转换、身份认定与权限门控，不含业务逻辑。身份认定集中在 `api/identity.py`：解析请求头或查询串里的成员标识与令牌、恒定时间比较、给出「须是成员」与「须是主持人」两个门控依赖，以及三句面向用户的拒绝文案。路由不得各自实现令牌比较或各自拼拒绝文案。发言触发的编排逻辑（每房间的待发言 FIFO、在途守卫、收束钩子）是接入层的运行时状态，落在 `api/ws.py`，不下沉到服务层。
- 应用服务层承载房间、配置、发言、结论与记忆的业务用例。本层没有「编排服务」对象：一次性路径与降级路径各自直接调用发言生成服务。
- 编排层为待发言队列、发言权与意愿判定三件内存态模块，由接入层的两条通道共读同一份。发言权在 `orchestration/floor.py`，与待发言队列同层同性质（内存态、按房间维护）；授予发言权的判定（主持人的 @ 才授予）也在该模块，两条通道共用同一个函数，不得在实时通道与 REST 路由里各写一份。
- 领域能力层提供检索、上下文组装、滚动摘要、来源标注与立场记忆。历史召回（记忆 L4）只有表结构而无代码路径，不得在业务逻辑里假定它可用。
- 模型适配层与持久化层位于底层，供上层调用。

## 框架与外部依赖隔离

- 编排为自研实现，不接外部编排框架。依赖清单中声明的 `ag2` 未被任何模块导入，`orchestration/ag2_adapter.py` 是一层不含框架调用的薄壳，无运行时调用方。若日后接入外部编排框架，只在该适配器与调度策略实现内落地，其余模块不得直接 `import` 该框架；跨层传参用本项目领域实体与接口。
- 模型调用只经 `models/` 的提供方接口；业务代码不得直接调用 DashScope SDK 或拼接其 HTTP 请求。
- 持久化只经 `persistence/`；业务层不得直接写 SQL、读写文件或操作向量库。
- 向量检索只经 `rag/`；业务层不得直接操作向量库客户端。

## 扩展点接入

抽象与扩展点见 `../../docs/architecture.md` 第 5 节。本版只有两个接口：

- 新增编排模式：实现 `SpeakerSelectionStrategy`。四个实现都已在 `orchestration/strategy.py` 中而均无运行时调用方，接入须另在接入层增加按房间编排模式选择策略的环节，并给出该模式的入队与放行规则——只补一个策略类不会让该模式生效。
- 新增模型提供方：实现 `ModelProvider`（含一次性对话、流式对话与嵌入三个方法），不改发言与检索链路。现有两个实现为 OpenAI 兼容与离线演示，按连接是否配了 API Key 选用。

技能、成员身份、会话通道、记忆压缩与长期召回五处没有接口抽象，扩展是改动相应模块而不是新增一个实现：

- 技能现为智能体内置提示词（人设/专长/发言风格）加发言节奏档位，扩展工具型技能须先引入一层可调用工具的抽象。
- 成员身份现为进房昵称加成员令牌，身份落在连接上。人类发言的来源标识一律取自连接身份，请求体里没有可填的来源字段；署名与导出按房内全部人类成员解析显示名，落库早于连接级身份的历史行其来源为字面值 `host`，继续按主持人回落，其余解析不到时回退通称而非空值。音色识别等其余身份来源须在身份认定处（`api/identity.py`）接入，接入后仍须落到「连接对面是谁」这一层，不得退回按界面推断。
- 会话通道现为单机 WebSocket 加 REST 与 SSE 降级，扩展为跨机网关须先抽象出通道层。
- 记忆压缩现为滚动摘要一种实现，替换压缩方式即替换 `memory/compress.py`。
- 长期召回本版未启用，启用须在记忆服务内新增召回路径并接入上下文组装。

## 事件与协议一致性

- 下行房间事件（阶段提示 `stage`、思考增量 `thought_delta`、发言增量 `message_delta`、发言 `message`、举手 `raise_hand`、举手队列变更 `raise_hand_update`、发言权变更 `floor_update`、成员名单变更 `member_update`、阶段结论生成中 `conclusion_started`、阶段结论完成 `conclusion_done`、房间状态 `room_state`、发言失败提示 `speech_failed`、上行拒绝提示 `rejected`）在接入层定义，房间界面的内联实时客户端按该事件名处理。结论生成的两个事件由 REST 结论端点广播——结论没有实时通道的上行分支，广播口在 REST 侧；生成期间发言暂停，`point`、`release` 与 `human_message` 以及 REST 的对应写端点都先读结论生成门闩，占用中一律拒绝「阶段结论产出生成中，请稍等」，两条通道口径一致。
- 上行消息（`point`、`release`、`dismiss`、`raise_hand`、`raise_self`、`withdraw_hand`、`human_message`、`room_state`）由接入层校验；校验不通过回 `rejected` 并附提示，连接不中断。`point`、`release`、`dismiss`、`raise_hand` 为主持人专属，来自非主持人连接时同样回 `rejected`。人类发言的两个受话者标识列表随 `human_message` 上行，受话智能体须在房间阵容内、受话成员须在房内成员名单中。
- 身份在实时通道以查询串携带，在接受连接之前校验，缺失或失效以 1008 关闭而不进入接收循环；在 REST 以 `X-Member-Id` 与 `X-Member-Token` 两个请求头携带。两条通道的门控范围必须一致：一处认主持人的操作，另一处也认；一处开放的读接口，另一处也开放。本版有一处不一致——主持人为自己举手在 REST 侧被拒并提示「主持人有话直接说，不必举手」，实时通道的 `raise_self` 未做该检查（见 `../../docs/runbook.md` 第 7 节）；触碰这两条分支时以 REST 侧的口径为准。
- 发言触发的编排状态（每房间单人发言守卫、待发言队列与发言权）属接入层与领域能力层职责，不下沉到发言服务：服务层只负责一次发言的检索、生成与落库，触发次序由接入层串行化，发言权由领域能力层持有而两条通道共读。
- 降级通道走 REST 与 SSE，帧名为 `stage`、`thought`、`delta`、`message`、`error`，同一校验以 HTTP 状态码与错误体呈现，不使用 `rejected` 事件名。两条通道的事件须同样下发：改动待发言队列、发言权、成员名单或新增发言的 REST 端点，成功后广播与其实时通道孪生分支同一形状的事件，否则一方降级就会让仍在线的其余客户端停在旧状态上。发起方自己收不到该广播——他正是在没有实时通道时才走这条路——故仍须在成功后重取房间、队列与消息。退出聊天室（`POST /rooms/{id}/leave`）同样按此口径：广播 `member_update`，发言权或举手有变化时另广播 `floor_update`／`raise_hand_update`。流式降级端点当前恒返回 401：房间界面直接发起该请求而未附带两个身份请求头，而端点要求主持人身份；经统一封装发起的其余降级调用都附带头，不受影响（见 `../../docs/runbook.md` 第 7 节）。
- 流式相关事件（`stage`、`thought_delta`、`message_delta` 与终结的 `message`）共用同一 `stream_id`，前端据此定位并替换流式气泡；终结的 `message` 在消息体之外并列携带截断标记。
- 新增事件类型时，同步更新接入层、房间界面客户端、降级通道与本文档第 4 节所列事件名。
