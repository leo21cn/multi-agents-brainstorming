# 规则 02 · 领域不变量

来源：`../../docs/concept-req.md`、`../../docs/srs.md`、`../../docs/user-stories.md`、`../../docs/data-model.md`、`../../docs/architecture.md` 第 7 节。以下为易被违反、且违反即算缺陷的不变量。

## 系统级与房间级分离

- 模型连接、知识库、智能体、角色卡是系统级实体，归管理员在系统初始化阶段配置，初始化后可在管理界面持续新增与调整。
- 系统级实体不归属任何房间；不得在房间实体上直接挂知识库或智能体本体。
- 房间经选用关系（RoomAgent）引用系统级智能体组建阵容。
- 管理界面负责系统级配置；房间界面只做选用与讨论控制。两者职责不得混用。

## 初始化最低要求

- 系统必须至少存在一个知识库与一个已绑定知识库的智能体。
- 未满足最低要求时，创建房间请求必须被拒绝并给出提示。

## 模型连接

- 模型连接为系统级实体，含名称、供应商类型、API 地址、API Key、可用模型名列表。
- API Key 入库但受保护：界面掩码、仅管理员可见、日志与导出不含、不下发前端明文；环境变量可作为默认值或覆盖。
- 模型接入统一走 OpenAI 兼容端点；非 OpenAI 兼容协议留待迭代。

## 智能体配置

- 可配项：模型连接与所选具体模型、一个或多个知识库绑定、角色提示词卡。
- 未选模型连接、未选模型、未绑定知识库或未命名时，不允许保存该智能体。
- 所选模型必须在该模型连接的可用模型名列表内。

## 知识库三维度

- 维度固定枚举：业务领域、项目管理与软件工程方法论、技术架构。
- 新增维度需修改 `KnowledgeDimension` 并同步检索与配置服务，不得硬编码维度到业务逻辑。

## 编排

- 默认编排模式为人类主持控制，本版仅完整实现该模式。
- 其余三种（固定轮询、AI 主持人调度、自由抢话）只保留调度策略接口，不实现内部逻辑，不得在默认路径之外引入自动发言。
- 默认模式下，未被点名且未被放行的智能体不得发言（验收标准 A-1：越权发言数为 0）。

## 插嘴

- 智能体不主动打断进行中的发言。
- 举手信号由轻量意愿判定产生，入待发言队列，不生成完整发言。
- 主持人放行触发该智能体发言；驳回将其移出队列。队列按信号到达顺序排列。

## 来源标注

- 每条发言记录其引用的知识库来源；检索无命中时标记无知识库引用且不阻断讨论。
- 结论文档的关键观点与分歧点必须标注来源智能体及其绑定知识库（验收标准 A-5：标注完整率 100%）。
- 导出记录每条发言必须保留来源智能体标识（验收标准 A-6）。

## 记忆边界

- 记忆随房间隔离；会话记忆与摘要记忆对房间内成员共享，立场记忆默认仅服务所属智能体。
- 知识与智能体配置跨房间复用，不属于记忆。
- 结论生成与导出以会话记忆为数据源。
