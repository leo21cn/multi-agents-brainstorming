# 规则 02 · 领域不变量

来源：`../../docs/concept-req.md`、`../../docs/srs.md`、`../../docs/user-stories.md`、`../../docs/data-model.md`、`../../docs/architecture.md` 第 7 节。以下为易被违反、且违反即算缺陷的不变量。

## 系统级与房间级分离

- 模型连接、知识库、智能体、系统设置是系统级实体，归管理员在系统初始化阶段配置，初始化后可在管理界面持续新增与调整。
- 系统级实体不归属任何房间；不得在房间实体上直接挂知识库或智能体本体。
- 房间经选用关系（RoomAgent）引用系统级智能体组建阵容。
- 删除受引用保护：被任何房间选用的智能体（含已结束房间）不可删除，服务端 409 返回中文文案「该智能体已被房间选用，无法删除」；智能体出参携带被选用房间数 `room_count`，管理界面删除前直接预告数量、不发必失败的请求；被智能体引用的连接与被智能体绑定的知识库同样 409 拒绝（中文文案）。
- 管理界面负责系统级配置；房间界面只做选用与讨论控制。两者职责不得混用。

## 初始化最低要求

- 系统必须至少存在一个知识库与一个已绑定知识库的智能体。
- 未满足最低要求时，创建房间请求必须被拒绝并给出提示。
- 未满足最低要求时，访问首页跳转到管理界面初始化状态视图并提示配置。

## 模型连接

- 模型连接为系统级实体，含名称、供应商类型、API 地址、API Key、可用模型名列表、嵌入模型名。
- API Key 入库但受保护：界面掩码、仅管理员可见、日志与导出不含、不下发前端明文；环境变量可作为默认值或覆盖。
- 模型接入统一走 OpenAI 兼容端点；非 OpenAI 兼容协议留待迭代。
- 嵌入模型名可空，空值按提供方缺省值解析，不得在实现层硬编码具体模型名。更换嵌入模型使既有向量与新查询向量不在同一空间，须重新入库文档；本版不做自动重嵌入。
- 连接的地址、凭据、可用模型名与嵌入模型名改动后对后续调用即时生效，不依赖重启服务。

## 智能体配置

- 可配项：模型连接与所选具体模型、一个或多个知识库绑定、提示词（人设、专长、发言风格）、发言节奏档位。
- 未选模型连接、未选模型、未绑定知识库或未命名时，不允许保存该智能体。
- 所选模型必须在该模型连接的可用模型名列表内。
- 发言节奏档位取值必须在三档之内，缺省为均衡；改动后对下一次发言即时生效，不依赖重启服务。

## 知识库三维度

- 维度固定枚举：业务领域、项目管理与软件工程方法论、技术架构。
- 新增维度需修改 `KnowledgeDimension` 并同步检索与配置服务，不得硬编码维度到业务逻辑。

## 编排

- 默认编排模式为人类主持控制，本版仅完整实现该模式。
- 其余三种（固定轮询、AI 主持人调度、自由抢话）各有一个调用即抛未实现的策略类，四个策略类都不接入运行路径；不得在默认路径之外引入自动发言。
- 默认模式下，未被点名且未被放行的智能体不得发言（验收标准 A-1：越权发言数为 0）。「点名」含协议上行的显式点名与人类发言中 @提及某一智能体两种形态，两者等价，均只允许该受话者发言。自主举手不改变本条：判定只产生举手，发言仍须经主持人放行。本条对人类成员同样成立：非主持人的成员未经放行或主持人 @ 指向而落库的消息数为 0。

## 连接级身份与发言权

- 人类消息的 `source_id` 一律取自连接身份，不得写成常量占位值，也不得从请求体读取——请求体里没有可填的来源字段，故无从替别人发言。
- 成员令牌只在发放那一刻随响应返回一次（进房或认领），任何读接口、日志与导出都不含；成员序列化一律经不含令牌的响应模型输出，不得裸返实体字典，否则加一列就会把令牌发给所有打开房间页的人。令牌以恒定时间比较校验，比较按 UTF-8 字节走。
- 实时通道在接受连接之前校验身份，缺失或失效以 1008 关闭，不得先进入接收循环再驱逐。REST 侧同一套身份经两个请求头携带，两条通道的门控范围必须一致。
- 讨论控制类操作在服务端只认主持人：开始、移交主持、结束、生成结论、导出、点名发言（含流式形态）、模拟举手、放行、驳回。界面不呈现入口不构成依据，越权调用一律拒绝且状态不变。读接口不加身份，房间标识即读凭据，此为单机演示的既有取舍，不得顺手给读接口加门控——那会把「读既有产出」也挡在门外。
- 放行人类举手与主持人的 @ 各授予一次发言权，发出一条消息即消耗；主持人自己不受约束，他本来就掌握节奏。发言权是内存态、无表、无迁移，进程重启即清空，房间结束时一并清空。授予判定只有一处实现，两条通道共用，不得在实时通道与 REST 路由里各写一份。
- 成员发出的 @ 只作受话者标注：既不触发智能体发言，也不授予另一位成员发言权，否则成员之间就可以私相授受而绕过放行。
- 昵称在房内人类成员中唯一，且不得与阵容内智能体同名——同名会让 `@` 解析出现二义，在进房时一次拒绝比事后定优先级规则干净。房间已结束时不接受新成员加入；既有成员可凭管理令牌认领，认领只重新发放令牌并把状态置回在线，不改成员标识，故既有发言与举手的归属不变。
- 成员带状态位（在线／已退出）。退出聊天室是服务端动作（`POST /rooms/{id}/leave`）：置已退出并清令牌（旧身份立即失效），清其发言权与排队举手并广播成员变更；主持人在房间未结束时须先移交或先结束（服务端强制，422 拒绝），不得留下「主持人是已退出成员」的房间。已退出成员不能被 @——受话者含已退出成员时整条消息被拒（REST 422／WS rejected，文案含「已退出聊天室，不在线」）、不落库、不触发生成；已退出成员不能被设为主持人（422「该成员已退出聊天室，不能设为主持人」）。成员行只增不减，已退出成员保留在名单中带标签呈现。

## 插嘴

- 智能体不主动打断进行中的发言。
- 举手信号有三个来源：智能体经意愿判定自主提出，主持人经房间界面举手栏的模拟入口代为产生，人类成员在底栏自己举手。三者都只入待发言队列、不生成完整发言，且在队列中带来源标注，混排在同一条队列里按到达顺序排列。模拟入口的位置与可见性为系统级可配置项，缺省显示，且只对主持人呈现。
- 举手的主体是智能体或人类成员，二者恰有一个非空，构造时即校验；「两者皆空」无从呈现给主持人，「两者皆有」则说不清放行的是谁。同一主体在活动队列中至多持有一条举手：智能体再举由重判处理，成员再举一次改写既有条目的意图而不追加。
- 主持人放行智能体的举手触发该智能体发言，放行人类成员的举手只授予其一次发言权而不触发任何生成；驳回将其移出队列。
- 出队只有三个原因：放行、驳回、撤回。撤回由重判产生（智能体自己不再想说）或由举手者本人产生（成员在放行前撤回自己那条），驳回由主持人产生，二者各占一个状态取值，不得互相顶替。结束房间只清空发言权，不动举手队列——队列没有清空原语，故已结束房间的举手仍留在队列中，其放行与驳回在界面上禁用；作废的是待发言 FIFO 里已排定的发言，它在房间已结束时于下一次泵出整体丢弃（见 `../../docs/runbook.md` 第 7 节）。
- 放行的举手已不在队列中时须给出带原因的回执，不得静默成功：举手会自行撤回之后，主持人点到过期条目属常态，静默会把界面留在一个永远不会兑现的生成占位上。驳回一条已不在队列中的举手按静默成功处理，期望状态已经成立。
- 点名作为协议能力保留，房间界面不提供其入口；人类侧的发言触发入口为 @ 定向提问与举手放行。

## 自主举手

- 触发点为每条新发言落定之后，人类消息与智能体发言均触发；仅在讨论中的房间进行，待开始与已结束的房间不做判定。
- 轮次挂在实时通道的收束钩子上：经降级通道落库的人类发言与经一次性接口生成的发言不触发判定，故自主举手与队列刷新只在实时通道可用时发生。
- 判定对象为除刚发言者与已被安排发言者之外的全体在席智能体。刚发言者由记忆中最后一条消息的作者认定，收束钩子不向轮次传递发言人；已被安排发言者含正在生成的与已在待发言队列里的，再问一遍只会产生重复举手。已持有自主举手者同样重判。主持人代填的模拟举手与人类成员的举手同样不参与重判：轮次只改写来源为自主的那些，判定无权改写主持人的意思，更无权替他或成员撤回。判定对象限于在席智能体，人类成员不被询问——他要不要说由他自己举手。判定提示词带上最新发言者的署名（智能体记其名，人类成员记为「主持人 某某」或「成员 某某」），署名进系统段而不进问题段，故离线演示提供方按固定标记切分问题的口径不变。
- 刷新是重判而非追加：一轮的产出是待发言队列在本轮上下文下的一张新快照——想说的进去、不想说的出来、还想说但换了说法的原位改写。只在每轮末尾追加会让队列单调增长，主持人面对的是十几条互相重复、意图过期的条目。
- 重判改写意图时保留 `raise_id` 与队列位置，只换意图文本：位置是主持人已经读过的次序，标识是他可能已经瞄准的按钮，每次刷新都重排会把放行变成一个打移动靶的操作。
- 判定失败按没有结论处理：既不新增举手，也不撤回已有举手。fail-closed 只约束新增，把一条已有举手表成撤回是另一种猜测——模型抖一下就让某个智能体静默失声，主持人还以为他真不想说了。
- 一轮内的判定并发发起并设上限，结果按房间阵容次序应用：判定之间没有依赖，串行只是把延迟乘以在席人数；按完成次序应用会让同一批人每次刷新后排法都不一样。
- 每房间同时只跑一轮，轮次与发言并发时合并重入，否则同一批智能体会被反复询问；合并期间落定的新发言记入待补集合，本轮收尾后补跑一轮，刷新不得被合并丢弃。补跑以循环实现，连续多轮欠账不会把调用栈堆深。
- 判定是一次轻量模型调用：关思考、限时、不受发言档位约束，只要一行 JSON，不要正文。单个判定在提供方限时之外另有硬界，线程池卡住时轮次也不会永不退出。
- 解析严格：只接受能取出一段 JSON 对象且意愿字段严格为真的回复，其余按不举手处理；超时与异常同样按不举手处理。判定是旁路增强，故障既不得中断讨论，也不得产生来源不明的举手（验收标准 A-18、A-20）。
- 自主举手开关为系统级可配置项，缺省开，读取开放而写入须令牌；改动对下一条消息即时生效，不依赖重启。关闭即整轮不跑，已有举手既不被改写也不被撤回。
- 判定所用的最新发言在轮次开始时取一次快照，轮次期间新到的发言留给下一轮，不在本轮内追逐；下一轮由待补集合保证一定会跑。
- 轮次引起的队列变化以一条队列更新事件下发，不逐条发举手事件：一轮可能同时改写、撤回与新增多条。

## 人类发言与定向提问

- 房间已结束后同样不再新增人类发言；该约束由服务端强制，界面禁用不构成依据。
- 人类发言可带两个受话者标识列表：智能体一列、人类成员一列，各自空列表表示未指向。任一受话智能体不在房间阵容内、或任一受话成员不在房内成员名单中，则整条消息拒绝并给出提示，不做部分接受——半接受会让落库消息的收件人与正文里的 `@名字` 对不上。重复标识在各列内按首次出现的位置去重。
- 两列并存而不合并：智能体列的名字与校验口径都锚在阵容内智能体，塞进成员标识会让「受话者不在房间阵容内」这条拒绝失去意义，也会让多受话者按书写次序依次应答掺进不会应答的对象。智能体列决定串行应答次序，成员列只决定发言权授予与界面标注；界面与导出呈现受话者时一律智能体在前、成员在后。
- 受话者标识落库于消息本体，不由正文中的 `@名字` 记号反推；记号是界面语法，服务端不做正文解析。
- 定向提问视同点名：落库后按受话智能体的书写次序依次触发其发言，问题原文同时作为本次发言意图用于检索。受话的人类成员不被触发生成，主持人的指向只授予其一次发言权。
- 定向提问遇同房间已有发言进行时，问题照常落库并广播，触发的发言排入该房间的待发言队列，前一次收束后依次进行，不丢弃、不上报失败。
- 人类发言的来源标识取自连接身份，不得写成常量占位值，也不得一律记成主持人；导出与上下文署名按房内全部人类成员解析显示名，落库早于连接级身份的历史行其来源为字面值 `host`，继续按主持人回落，其余解析不到时回退通称。

## 发言生成

- 房间已结束后不再新增发言；该约束由服务端强制，不仅依赖界面禁用操作。
- 生成期间持续下发阶段提示、思考增量与正文增量，落库在全部增量到达后一次完成；落库内容必须与正文增量拼接结果一致（验收标准 A-12），思考增量不参与拼接。串行应答下该口径逐条成立，每次发言各用自己的流标识。
- 生成中途失败不落库部分内容，仅上报失败并允许重新发起提问。
- 同一房间同时只允许一次生成；忙时触发的发言（点名、放行举手、多受话者的后续应答）排入该房间的先进先出队列依次进行，不拒绝也不并发写入共享记忆。队列在房间已结束时作废，避免连播一串失败提示。
- 在途守卫须记下正在发言的智能体，而不是只记「本房间有人在说」：判定轮次要把这个人排除在外，他的发言还没落库、上下文里还没有他自己，只记房间会在主持人生成中途放行时给他再挂一条新举手。
- 放行举手时沿用该次举手登记的发言意图，不得丢弃；放行遇忙同样排队，意图随队列保留。

## 发言节奏

- 档位约束优先于发言风格：正文长度与结构一律由提示词末位的要求段按档位决定，发言风格只决定视角与语气。风格文本中不得出现把回答推向长文的指令。要求段以完整句收束为硬要求，不得写入许可半截收场的表述。
- 正文字数按档位固定为快闪 240、均衡 600、深思 1800，以字符数计，与上下文预算同一计量口径。该数值是写进提示词的目标，由模型自行收束；客户端只在其 1.5 倍的安全界（360／900／2700）处兜底，且兜底不得逐字硬切，须在句界就地收束。断流由流式循环按字符数实现，不得改用 `max_tokens`——各家对该参数是否涵盖思考的语义不一致。
- 正文增量以完整句为粒度下发，故收束时无需回收已下发内容，落库与界面呈现一致。子句界与硬切只在首句就超出预算时作为退让，以免产出空正文；已发出过内容则不得退让，否则收束处又成半句。
- 思考内容是过程信息：不落库、不进导出、不进任何记忆层、不进上下文组装。界面以默认折叠区呈现，收尾替换后随气泡消失。
- 截断标记随正文落库，且只在确有内容被丢弃时为真——正文恰好填满安全界不算截断，模型自行收束在目标内更不带标记。已落库的正文可能是收束在句界的残篇，房间界面必须呈现截断标注，导出必须在对应行尾标注，二者都取落库标记而非重新推断。
- 「思考中」阶段惰性下发：首个思考增量到达才给出。关思考档位与不产推理内容的离线演示提供方都不得出现该阶段，界面不得显示一个永远等不到内容的阶段。
- 思考预算的支持与否按模型名前缀判定，判定结果由后端下发，前端不得重复实现前缀表。能力不足可以降级，但降级必须显式：管理界面标注该模型不支持思考分级，运行期端点拒绝思考参数时去掉参数重试一次并下发可见的阶段文案。静默降级视为缺陷。
- 重试只去掉思考参数，档位本体保留，安全界不因重试而失效。已下发过任何片段则不重试，否则客户端看到重复内容。

## 来源标注

- 每条发言记录其引用的知识库来源；检索无命中时标记无知识库引用且不阻断讨论。
- 结论文档的关键观点与分歧点必须标注来源智能体（验收标准 A-5：标注完整率 100%）。界面与 Markdown 文档只呈现智能体名；所绑知识库保留在来源标注数据（`source_annotations` 与各条的 `source.kbs`）里供追溯，不得因呈现简化而丢掉数据。
- 导出记录每条发言必须保留来源标识（验收标准 A-6）；带受话者的记录逐个保留全部受话者，智能体在前、成员在后。来源与受话者一律以显示名呈现，不落原始标识串；多位人类成员各自按自己的显示名呈现，不得一律记成主持人或回退「人类成员」通称。

## 结论综合

- 结论文档的章节分两条来路：命题、关键观点与分歧点三章由房间命题与会话记忆确定性地给出，关键观点与分歧点逐条带来源标注；初步结论／建议为模型必写章，其后 0 至 10 章由同一次综合调用按本次讨论的实际内容归纳。`sections` 的键序即章节序，前四键固定，其后各键的键名即章标题。命题只作文档头，不重复成一章。
- 章名由模型自拟，不设禁用名单：「行动项与负责人」「待定项」「风险」与模型自拟的说法在提示词里并列为同权重候选，用不用只看讨论里有没有对应内容。把文体偏好做成硬校验的代价不成比例——模型反复吐同一个词时，产出会从「章名不合口味」退化为「整份文档生成失败」，而主持人除了重试无从处置。
- 与四个固定章名重名仍拒绝，理由是键冲突而不是文体：命题为字符串、关键观点与分歧点为带标注的列表、初步结论／建议为必写章，额外章同名会让同一份 `sections` 里出现两种形态的值，渲染与前端都无从分辨。章名先去首尾空白与 `#`、`*` 记号再校验，否则「## 风险」与「风险」会被当成两章；归一后不超 20 字、不两章同名。
- 章长以 2000 字为目标、2400 字为安全界：目标写进提示词由模型自行收束，安全界内一字不动，故稍微超出目标是允许的；只有超出安全界才动刀，且复用发言长度那套句界收束（整句、子句、硬切三级回退），产出文档里不出现半句。
- 各章不得以指向他章的占位句代替综合（如「见关键观点与分歧点」「见分歧点」「待指派」）：占位句读起来像成稿，实则把综合推给读者，而主持人触发生成正是为了省下这一步。讨论确未涉及某一章时不写那一章，也不编造。
- 综合提示词以固定标记开头，回复只接受一个 JSON 对象，首键须为初步结论／建议、其后依次为额外章；缺必写章、章名不合规、额外章超 10 个、值非字符串或为空、非法 JSON 一律判为不可解析。模型常把中文引号写成半角双引号而使整份回复成为非法 JSON，故解析失败时先按扁平对象的结构给内层引号补转义再解一次——键的收尾引号后必是冒号、值的收尾引号后必是逗号或右括号，据此与正文引号区分；仍不可解析才判为失败。要求段进系统段，命题、讨论记录与已抽取要点进问题段，与意愿判定同一套口径。
- 综合目标取系统设置的 `conclusion_conn_id` 与 `conclusion_model`，二者成对给出或成对留空；设置留空、所指连接已删除或模型名已不在该连接的可用模型名列表内时，回落房间阵容首位智能体（按入席时间排序）的连接与模型。取向在每次生成时读取，故设置改动无需重启。
- 综合失败即整份文档不生成、不落库部分内容，返回可重试的失败响应；不得为凑章数而回落占位句——半份成稿比一次明确的失败更难被发现。
- 生成期间全房间进入等待并暂停发言：结论端点占用房间的生成门闩后广播生成中事件、结束（无论成败）广播结果事件并释放门闩，同一房间同时只允许一次生成，占用期间的再次触发被拒。发言触发（点名、放行、人类发言）在 REST 与实时通道两条路径上都先读同一把门闩，占用中一律拒绝「阶段结论产出生成中，请稍等」；举手入队与撤回不拦——举手不产生发言，放行才是发言触发点。房间界面据此呈现等待模态并禁用底栏，成功后各客户端自动打开产出模态。生成是同步阻塞调用，须经工作线程执行，不得阻塞事件循环。
- 离线演示提供方按提示词标记给出由提示词内容派生的确定性回复：必写章围绕命题起笔，额外章恒为两章且标题取自讨论要点原文的前 12 字，故章数可变与标题自拟两条路径在无密钥时同样被测试触及。关键观点取发言前 60 字、分歧点取立场记忆即同一条发言前 200 字，单条发言时两个要点的前 12 字必然相同，故标题去重是必经路径而不是防御性代码。派生只读提示词，不读库；固定章名在模型层另立一份常量，因为模型层不得反向依赖服务层。

## 语音输入

- 语音输入是输入通道而非发言触发：录音期间转写文本经实时通道逐段下发并实时显示在发言输入框（已有内容以空格分隔为前缀、录音期间输入框锁定），停止后定稿留在输入框可修改，不自动发送——主持人按发送语义、成员按举手意图，语音不绕过任何发言权与门控。
- 转写模型在管理后台专项配置（系统设置 `asr_conn_id` 与 `asr_model`，成对给出或成对留空、读写须管理令牌；模型名为自由文本、缺省 `qwen-audio-3.0-asr-flash-streaming`——Qwen-Audio-3.0-ASR 流式型号）；未配置时 `asr_begin` 回 `asr_error` 引导配置。
- 流式转写经房间实时通道事件：上行 `asr_begin`/`asr_audio`（base64 PCM 帧）/`asr_end`，下行 `asr_text`（增量）/`asr_done`（定稿）/`asr_error`，只回给发起者本人；服务端走 DashScope 实时识别 WebSocket（任务制双工），每连接同时只允许一个语音会话，连接断开即终止。批量转写 `POST /rooms/{id}/asr` 复用同一会话，只对房内成员开放（转写消耗模型配额），空录音与超 2MB 被拒，失败 502 可重试；音频只在内存中处理，不落盘、不入日志。

## 外部知识库组合检索

- 自有知识库与中心知识库（my-center-knowledge-lib）兼有、组合使用，内容**不导入**本系统（Document/Chunk 零改动，只存挂接关系 `ExternalCorpusLink`）。
- 连接配置（`ext_kb_url`/`ext_kb_token`/`ext_kb_enabled`）为系统级，令牌受保护（掩码回显、仅管理令牌读写、日志与导出不含）；未启用时零外部调用、检索为纯本地。
- 挂接为知识库级：别名全局唯一且不与知识库名/智能体名重名（409），同一知识库不重复挂接同一语料库、外部语料库不存在或已归档时拒绝（422）；挂接即生效、解除即回到纯本地（无启停开关）；外部语料库被删/归档后挂接保留、检索跳过并标注失效。
- 发言检索 = 本地 Chroma + 各挂接外部语料库的远程检索，并发、源内归一化后**等权合并**、按内容哈希跨源去重、统一截断；外部单源失败按 0 条处理并显式记入降级日志（不进上下文与界面），全部外部源不可用即退化为纯本地检索且讨论不中断，静默降级视为缺陷；发言界面与结论文档的来源标注口径不变（别名仅管理界面呈现）。

## 记忆边界

- 记忆随房间隔离；会话记忆与摘要记忆对房间内成员共享，立场记忆默认仅服务所属智能体。
- 知识与智能体配置跨房间复用，不属于记忆。
- 结论生成与导出以会话记忆为数据源，取该房间的全量发言而不取摘要记忆。
