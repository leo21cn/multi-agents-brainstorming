# 火花会 Sparkwave（程序）

人机混合头脑风暴工具的第一版单机演示系统：人类成员与智能体在同一房间内围绕命题讨论，智能体在每条新发言后自主举手表达意愿，举手随讨论刷新——仍想说的换成针对新上下文的一句话，不想说的自行撤回；主持人控制发言节奏并决定放行谁插嘴；一条消息可 @ 多位智能体，各受话者按书写次序依次应答；讨论到阶段时生成结构化结论文档并导出完整发言记录。

多人讨论经邀请链接进房：受邀者打开链接先落到进房落地页，看清这是什么会、谁主持、有哪些智能体与谁已经进来，填一个昵称即取得连接级身份，此后以该身份发言。本阶段非主持人的人类成员与智能体同权——须举手并被主持人放行，或被主持人 `@`。

- 权威文档：`../docs/`（概念需求、SRS、架构、用户故事、数据模型、视图规格、实施计划、运行手册、本机跑通指南、测试语料）。已知缺陷集中记于 `../docs/runbook.md` 第 7 节。
- 协作约定：`AGENTS.md` 与 `rules/`。

## 技术栈

Python 3.11+、FastAPI（REST + WebSocket + 服务端推送事件流）、SQLModel（SQLite）、向量库（Chroma，仅在依赖未安装时回退内置实现；打开失败不降级）、自研编排（待发言队列、发言权、意愿判定与自主举手轮次，均为进程内存态；不接外部编排框架）、免构建静态前端（原生 HTML/CSS/JS，由后端 StaticFiles 同进程托管；第三方能力以单文件 vendor 纳入，现为发言正文渲染器 markdown-it）。

## 快速开始

```
# 1) 安装依赖
cd backend
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt   # Windows
# 或 source .venv/bin/activate && pip install -r requirements.txt  # macOS/Linux

# 2) 入库测试语料（读取 ../docs/testdata）并建系统级配置
cd ..
make seed

# 3) 启动
make up            # http://localhost:8000/healthz ，演示台 http://localhost:8000/app（首页「头脑风暴房间」→ 建房页 /lobby/），管理后台 http://localhost:8000/admin/
# Windows 快捷启动（项目级技能 start-server，见 skills/start-server/SKILL.md）：
powershell -File scripts/start_server.ps1             # 后台启动（日志写 program/server.log，自动健康检查）
powershell -File scripts/start_server.ps1 -Foreground # 前台启动（在自己终端里跑最持久，Ctrl+C 停止）

# 4) 测试与基准
make test
make benchmark
```

> 本机若无 `make`，用等价的跨平台入口：
> `python tasks.py seed` / `python tasks.py up` / `python tasks.py test` / `python tasks.py benchmark`

## 模型接入

- 系统级「模型连接」承载 API 地址、API Key、可用模型名与嵌入模型名，统一走 OpenAI 兼容端点。嵌入模型名留空时使用提供方缺省值；更换后既有向量失效，需重新入库文档。
- 配置了 API Key 时使用真实模型（默认 DashScope/Qwen 兼容端点）；未配置时使用**离线演示提供方**（确定性输出），用于本地跑通闭环。设置 `DASHSCOPE_API_KEY` 即切换为真实模型。
- API Key 入库但受保护：出参一律掩码，测试断言明文绝不回传。
- 连接与智能体的配置改动对后续调用即时生效，无需重启服务；已打开的房间页在重新获得焦点时自动重取配置。

## 接口概览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/healthz` | 健康检查 |
| POST | `/admin/login` | 管理后台登录校验 |
| PATCH | `/admin/token` | 修改访问令牌 |
| POST/GET/PATCH | `/model-connections` | 模型连接（出参掩码） |
| POST/GET | `/knowledge-bases`、`/documents` | 知识库与文档入库 |
| POST/GET | `/agents` | 智能体（含提示词与发言节奏档位；校验模型/知识库；下发思考分级能力判定与被选用房间数 `room_count`；删除被房间选用的智能体返回 409 中文文案，管理界面删除前直接预告） |
| GET | `/system/init-status` | 初始化状态（建房门槛） |
| GET/PATCH | `/system/ui-options` | 界面与行为选项（是否显示模拟举手入口、是否允许智能体自主举手）；GET 开放，PATCH 须令牌且为全量覆盖 |
| GET/PATCH | `/system/asr-model` | 语音转写模型（连接 + 转写模型名，缺省未配置、模型名自由文本如 `qwen-audio-3.0-asr-flash-streaming`）；读写均须令牌，二者成对给出或成对留空 |
| GET/PATCH | `/system/conclusion-model` | 结论综合所用的模型连接与具体模型；读写均须令牌，二者成对给出或成对留空，模型名须在所选连接的可用列表内 |
| GET | `/external-kb/corpora` | 外部语料库列表（走连接层快照，响应附 `state`/`refreshed_at`）；须令牌，未配置 422 |
| GET/PATCH | `/system/external-kb` | 外部中心知识库连接（API 地址/访问令牌/启用）；读写均须令牌，令牌只回掩码、留空表示不修改，启用时地址与令牌必填 |
| GET/POST | `/external-kb/healthz` | 外部连通探测：GET 走连接层快照（快）；POST 携带表单当前值实时测试（不落库，留空回退已保存）；均须令牌，未配置 422、外部不可达/令牌无效 502 |
| GET/POST、PATCH/DELETE | `/knowledge-bases/{id}/external-links` | 外部语料库挂接（知识库级，别名全局唯一且不与知识库/智能体重名 409；重复挂接/语料库不存在或已归档 422；出参含 stale 失效标记）；均须令牌 |
| POST | `/external-kb/retrieval-test` | 知识检索测试验证（独立分区）：与发言同算法的分组检索（本地/外部/合并 + 降级清单），一次性内存态不落库；须令牌，查询非空且 ≤200 字、范围缺省全部知识库 |
| POST/GET | `/rooms`、`/rooms/{id}` | 房间；命题最多 200 字（建房时校验，越界返回 422）；单个房间的响应含阵容与当前发言权持有者 |
| POST | `/rooms/{id}/join`、`/claim` | 自助进房（昵称必填、房内人类成员中唯一且不与阵容内智能体同名，房间已结束时拒绝）与凭管理令牌认领既有身份（重新发令牌并把状态置回在线）；成员令牌只在这两个响应中各出现一次，此后不经任何读接口下发 |
| GET | `/rooms/{id}/members` | 成员名单（响应不含令牌字段、含状态字段：在线／已退出） |
| POST | `/rooms/{id}/start`、`/host`、`/end` | 开始讨论、移交主持、结束房间（均只认主持人；移交主持的目标成员已退出时 422 拒绝） |
| POST | `/rooms/{id}/leave` | 退出聊天室（服务端动作：置已退出并清令牌、清发言权与排队举手；主持人在房间未结束时须先移交或先结束，否则 422） |
| POST | `/rooms/{id}/speak`、`/speak-stream`、`/messages` | 点名发言（一次性／流式；协议能力，房间界面不提供入口；流式可带 `directed_from` 作焦点锚点）、人类发言（可带受话智能体与受话成员两个标识列表；须携带成员身份，非主持人另须持有发言权） |
| POST | `/rooms/{id}/asr` | 语音转写批量路径（须成员身份；PCM 二进制上传，转写模型未配置 422、失败 502 可重试；音频不落盘；房间页语音按钮走实时通道流式事件，不调本接口） |
| POST/GET | `/rooms/{id}/raise-hand…` | 举手（主持人代填智能体）、放行、驳回、成员自举手与撤回；队列项含来源（自主／模拟／成员）与意图 |
| POST | `/rooms/{id}/conclusion`、`/export` | 生成结论、导出记录（只认主持人；既有产出的读取与下载对全体成员开放）。结论的关键观点与分歧点由记忆抽取并带来源标注，初步结论／建议与其后各章由一次模型综合按本次讨论归纳；综合失败时整份文档不生成并返回可重试的失败响应。生成期间暂停发言：触发即广播生成中事件、房间内所有客户端呈现「阶段结论产出生成中，请稍等…」等待模态，发言触发（点名、放行、人类发言）在 REST 与实时通道一律被拒，同一房间同时只允许一次生成，完成后广播结果事件、各客户端自动打开产出模态 |
| WS | `/rooms/{id}/ws?member_id=…&token=…` | 房间事件（stage/thought_delta/message_delta/message/raise_hand/raise_hand_update/floor_update/member_update/conclusion_started/conclusion_done/room_state/speech_failed/rejected）；语音转写走同一通道：上行 `asr_begin`/`asr_audio`/`asr_end`，下行 `asr_text`（增量）/`asr_done`（定稿）/`asr_error`；身份在接受连接之前校验，不通过以 1008 关闭且不进入接收循环 |

> 智能体发言以流式下发：先阶段提示（检索知识库、思考中、生成中；关思考档位时「生成中」提前给出，故只呈现两个阶段），开思考档位下思考增量先于正文增量到达并只在界面折叠呈现、不落库，正文增量以完整句为粒度下发、超出档位字数目标的安全界时在句界收束并标记截断，全部增量到达后正文整体落库；实时通道不可用时发言生成自动改走 `/speak-stream`，帧名 `stage`/`thought`/`delta`/`message`/`error`——该流式降级路径当前恒返回 401，因为页面直接发起该请求而未附带两个身份请求头（见 `../docs/runbook.md` 第 7 节）。

> 人类发言须携带成员身份，来源记为该连接的身份而非一律记成房间主持人；以 `@名字` 定向提问阵容内的一位或多位智能体时，问题以带受话者列表的消息落库，各受话者按书写次序依次自动发言，视同点名；任一受话智能体不在阵容内、任一受话成员不在房内成员名单中、任一受话成员已退出（整条被拒并提示「…已退出聊天室，不在线」）、房间已结束、发言者未持有发言权，均整条被拒，实时通道回 `rejected`，降级通道回 HTTP 422 或 403。降级路径为先落库消息、再对每个受话者依次调用 `/speak-stream` 并透传该条消息的标识。同房间的发言触发（点名、放行、多受话者应答）排入待发言先进先出队列串行派发，忙时不丢弃、不拒绝。`@` 也可指向房内其他人类成员：主持人的 `@` 授予该成员一次发言权，等同放行；成员的 `@` 只作受话者标注，既不授予发言权也不触发智能体生成。

> 配置写操作与 `/model-connections`、`/documents`、`/system/conclusion-model` 的读取须携带请求头 `X-Admin-Token`；`/agents`、`/knowledge-bases`、`/system/init-status`、`/system/ui-options` 的读取与房间接口开放，选项的响应只含选项本身、不携带访问令牌。令牌存于数据库系统设置键 `admin_token`，缺省 `111111`，可在管理后台左侧「管理后台访问令牌修改」分区修改；界面与行为选项存于键 `show_raise_sim` 与 `auto_raise`，在管理后台左侧「界面与行为选项」分区修改；结论综合模型存于键 `conclusion_conn_id` 与 `conclusion_model`，在左侧「功能模型配置」分组下的「结论综合模型」分区修改，留空或所指连接与模型名失效时生成结论回落该房间阵容首位智能体的连接与模型。管理界面进入时要求登录；系统未初始化达标时访问 `/app` 跳转到 `/admin/?init=1`。

> 房间界面的控制面为顶栏动作（产出、邀请成员、结束房间、退出聊天室）加底栏发言输入与主持人的斜杠技能（整段输入以 `/` 开头即弹出候选层，含「阶段结论」与「导出发言记录」两项，方向键移动、回车或 Tab 执行并清空输入，执行成功后打开产出模态），举手栏承载待发言队列与放行、驳回并在栏顶提供模拟举手入口，队列项对自主举手追加「自主」标签、对人类成员自己的举手追加「成员」标签，队列随讨论刷新而既有条目的位置不变；不提供点名与切换房间入口，人类侧的发言触发入口为 `@` 定向提问与举手放行。底栏另有语音按钮：点击开始录音，说话期间转写文本经实时通道逐段下发并实时显示在输入框（已有内容以空格分隔为前缀），再次点击停止后定稿留在输入框可修改、不自动发送，转写模型在管理后台左侧「功能模型配置」分组下的「语音转写模型」分区配置（缺省 `qwen-audio-3.0-asr-flash-streaming`——Qwen-Audio-3.0-ASR 流式型号）。知识库可挂接外部中心知识库语料库：智能体发言检索为本地与外部**等权合并**的组合检索，内容不导入本系统，外部不可用时显式降级为纯本地、讨论不中断。退出聊天室对全体成员可见：主持人退出前须指定另一位人类成员接任主持，唯一人类成员退出时经确认后结束房间，退出即清本标签页身份并回退首页（成员行保留，重新进房走邀请链接并认领）。邀请成员模态只给出房间链接与复制按钮，受邀者一律自助进房。底栏按身份与发言权变形：主持人随时可发；成员无发言权时键入的那一句即举手意图、按钮为「举手发言」，其上提示条为「举手并经主持人放行后才能发言」并附一个 × 供本人关掉（记在标签页级，另开标签的人照旧看到）；已举手时输入框锁定并保留该句、按钮为「撤回举手」；获发言权时原句回填、提示条给出放行或被提问的口径、按钮回到发送，后两条状态提示不带 × 也不因入门说明被关掉而消失。成员视角不呈现结束房间、邀请成员、模拟举手、放行与驳回，键入斜杠也不弹技能候选层，产出模态对全体成员开放而只留既有产出的下载链接。选项改动后，已打开的房间页在重新获得焦点时随其余配置一并重取并生效；自主举手的开关由服务端在每轮判定开始时读取，同样即时生效，关闭后已有举手既不被改写也不被撤回。

> 身份与发言权：进房或认领取得的成员令牌是连接级身份的唯一凭据，REST 经请求头 `X-Member-Id`、`X-Member-Token` 携带，实时通道经查询参数携带，前端存标签页级会话存储（键 `sw.member.{room_id}`），故同一浏览器另开一个标签打开同一链接即为另一个人。令牌只在发放时出现一次，成员名单等读接口一律不下发；显示名与是否主持人每次由成员名单重新解析，不取自会话存储，故主持权移交即时生效。讨论控制类操作在界面上只对主持人呈现，服务端另有一层同样只认主持人：非主持人携带有效身份调用返回 403，身份缺失或失效返回 401，房间状态一律不变。发言权为内存态、按房间记成员标识集合，一次一发：放行人类举手或主持人 `@` 人类成员即授予一次，发出一条即消耗，主持人不受约束，房间结束时整体作废；集合随房间响应与 `floor_update` 事件下发，故刷新与重连后不丢，而举手时键入的意图只经实时事件回填。身份失效时实时通道以 1008 关闭，界面清掉本地凭据并回落进房落地页；换了浏览器或清了标签页数据之后，凭管理令牌在落地页认领即可取回原身份，成员标识不变。

## 验收

`make test` 覆盖功能验收 A-1..A-21 与差异化指标；`make benchmark` 跑通基准命题并输出来源一致率、标注完整率、越权发言数与导出一致性。`benchmark` 目标与 `tasks.py benchmark` 都直接调用基准函数并打印指标，恒以 0 退出；要拿退出码须直接跑 `./backend/.venv/Scripts/python.exe scripts/run_benchmark.py`（见 `../docs/runbook.md` 第 7 节）。
